Banker's inside the timetable engine

Booked rooms and teacher-periods are never handed back during a planning cycle, so the engine runs the algorithm with release = off: a process "finishes" by consuming its remaining Need. Two checks use it: (1) a whole-batch pre-check — sections are the processes, and rooms plus each teacher's free periods are the resource types; and (2) a per-session gate — a practical needs a room and all its teachers for two periods, so each period is granted only if the state stays safe. Press the button to plan every section as a dry run (nothing is saved) and read the engine's log.

Wait-for graph & deadlock detection

A re-allocation request that targets a room/period held by another class has to wait. Waiting requests form a graph (A → B means "A waits for B"). A cycle means nobody can ever move on their own — a deadlock — and it is detected (Tarjan's strongly-connected components) and reported instead of failing silently. Recovery breaks "hold and wait" by applying every move of the cycle atomically in one transaction.
